## Verified diagnosis

The cloud audit was directionally accurate. AgentLab is an advanced local
internal Alpha with real governance loops, Project Brain, role execution,
recovery, evidence ingestion, cost controls, Operator State, Domain Packs, and
production-oriented content workflows. It is not yet an unattended Production
OS.

Highest-priority verified defects:

1. **Evidence lineage can be misrepresented.** Current acceptance assembly can
   combine a new Writer route with an unrelated historical trusted run. A
   tracked accepted run executed by Agy/Gemini was later projected as if it
   proved Claude Code plus DeepSeek readiness.
2. **The dirty worktree is not green.** The 2026-07-16 snapshot collected 2715
   tests and reproduced five focused failures: acceptance documentation drift,
   NarrativePlanner worker-matrix disagreement, and route-catalog size drift.
   Canonical acceptance was `fail` with 25 pass, 5 candidate, and 2 fail.
3. **Evidence strength is not uniformly represented.** Legacy 3E review can
   accept claimed test names found in text. A separate execution-log gate checks
   selected logs, but the platform lacks one system-wide distinction between a
   claim, captured log, independent rerun, and trusted CI.
4. **Critical paths can degrade silently.** Broad exception handling is common;
   Project Brain contains fallbacks that swallow errors and still report an
   apparently successful result.
5. **Production delivery foundations are incomplete.** CI is centered on one
   Ubuntu/Python 3.11 job. Reproducible packaging, dependency locking, supported
   OS/Python matrix, typing, coverage, security scanning, install/upgrade tests,
   migration policy, release artifacts, and licensing closure are incomplete.
6. **Schemas and state backends lack central lifecycle governance.** Numerous
   versioned YAML contracts exist, but there is no central registry, declared
   compatibility window, complete migration chain, or optional transactional
   backend.
7. **Domain Packs exist but do not form a complete plugin seam.** Narrative,

### R3 — Govern schemas and state storage

Goal: make durable state upgradeable, recoverable, and backend-independent.

Required changes:

- Add a storage interface and optional SQLite event-store backend.
- Preserve human-readable YAML projections and deterministic export/import.

Gate: N-1 fixtures migrate to N, repeated migration is idempotent, interrupted

### R4 — Make degradation observable and test real failures

Goal: prove recovery behavior against real local processes rather than only

Required changes:

  Brain paths. Replace silent critical fallbacks with structured events.
- Every allowed fallback records exception type, affected capability, degraded
  state, operator-visible reason, retryability, and next action.
- Build deterministic local fake-provider and fake-CLI fixtures.
- Exercise timeout, non-zero exit, malformed output, quota exhaustion,
  disconnect, stuck process, child-process-tree cleanup, concurrent tasks,
  idempotent retry, failover, and resume.
- Run fault E2E on Linux and macOS without paid providers.

Gate: no critical-path silent fallback remains; every injected fault has a
traceable event, bounded termination, correct retry decision, and recoverable
state where promised.

- Prove the seam with a minimal non-narrative example that requires no generic

Placing this file at the root does not start repair automatically. Because it is
the fixed `PROJECT_HANDOFF.md` entrypoint, AgentLab can include it in future run
context, but an operator must still create and authorize each phase run.

```bash
./agentlab.sh init-task \
  --project AgentLab \
  --task-id task_mainline_repair_rN \
  --request-file PROJECT_HANDOFF.md \
  --no-auto-slug

  --project AgentLab \

  --project AgentLab \
  --task-id task_mainline_repair_rN \
  --dry-run
```

declare:

- `plan_status`
- `missing_facts`
- `must_read_artifacts`
- `allowed_files` and `forbidden_files`
- `dispatch_units`
- `acceptance_criteria`
- `evidence_required`
- `commands_allowed` and `commands_forbidden`
- `rollback`
- `self_check`
- `human_decision_points`

Allowed autonomy after explicit phase authorization:

- Modify only phase-allowed files in the isolated repair worktree.
- Run local deterministic checks and approved test commands.
- Generate run-local evidence, recovery artifacts, and acceptance candidates.
- Create local commits only after the phase's automated gates pass.

Always requires human approval:

- Freezing or changing the current WIP checkpoint.
- Real external model/provider calls and `run-pipeline --execute`.
- Dependency installation that changes the environment.
- Destructive Git/filesystem operations or irreversible migration.
- Push, Draft PR, PR mutation, merge, tag, release, deployment, and publication.
