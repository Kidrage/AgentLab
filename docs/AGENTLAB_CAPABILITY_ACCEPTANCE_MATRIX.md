model. It maps the user's target capabilities to deterministic evidence, live
evidence, known gaps, and repeatable checks.

## Current Architecture Baseline

| Role | Current executor | Current contract |
|---|---|---|
| Supervisor | Hermes + OpenAI Codex OAuth, GPT-5.6 Sol (`xhigh`) | `hermes_supervisor` |
| Observer | Agy + Gemini 3.5 Flash High | `agy_observer`; independent multimodal evidence |
| Observer capacity fallback | Same Agy shell + Claude Sonnet 4.6 | Only for governed Gemini `quota_exhausted`, `rate_limited`, or `model_unavailable`; text/image/PDF |
| Writer | Claude Code + DeepSeek V4 Pro | `claude_writer` |
| Researcher | Hermes + xAI OAuth + Grok 4.3 | `grok_research` |
| ArtifactProducer | Hermes + xAI OAuth + Grok 4.3 | `grok_media`; candidate-only |

The Gemini and Claude Agy routes are independent subscription pools. Their
declared five-hour and weekly durations do not reveal the limit, remaining
capacity, or reset time. Those fields are also unknown for current OpenAI Codex
and xAI subscription pools until a safe run-local observation records them.

Authentication and reachability never imply available capacity. Safe discovery
is restricted to `agy models` and provider-scoped
`hermes auth status <provider>`.

Visual acceptance is independent from generation. `grok_media` returns a
run-local candidate; an Observer must inspect the actual asset. Distinct
Reviewer and Verifier role sessions are required: the Reviewer covers aesthetic,
continuity, technical, and factual-safety evidence, while the Verifier checks
asset integrity, evidence-chain completeness, reviewer independence, and the
promotion boundary. Producer self-acceptance is forbidden; `pending`, `unknown`,
or missing evidence blocks promotion.

Status meanings:

- `pass`: the cited current or explicitly frozen historical contract is met.
- `candidate`: live or dry-run evidence exists, but it is not production
  acceptance.
- `warn`: orchestration works, but quality, scale, or live-provider evidence is
  incomplete. The current capability report may have zero `warn` rows while its
  overall status remains `warn` because candidate/blocked rows still exist.
- `blocked`: the implementation has an adapter or contract, but live execution
  is waiting on credentials/provider stability.

## Current Conclusion

AgentLab now has a coherent split:

```text
code task -> code_factory
known non-code task -> configured production_pack
unknown complex non-code task -> production-pack synthesis candidate
simple one-shot non-code task -> generic/artifact light path
```

The code factory path is still intact. The repaired non-code paths no longer
need to pretend to be software implementation tasks, and the unknown-domain
path can synthesize a governed production pack instead of requiring a hand-built
pipeline every time.

The current executor architecture is now explicit:

- Hermes + GPT-5.6 Sol / `xhigh` owns Supervisor work.
- Agy + Gemini owns Observer work; Claude is a same-shell, independent-pool
  fallback only for Gemini quota exhaustion.
- Claude Code + DeepSeek V4 Pro owns Writer work.
- Grok 4.3 through Hermes/xAI uses `grok_research` for research and
  `grok_media` for candidate media production.

The frozen 2026-07-12 goal-level audit remains `complete` for its original
scope. Its Agy Writer, GPT-5.5 coalescing, and generic Grok evidence is
historical; it does not override current role authority.

No subscription pool should be described as available merely because auth or a
smoke passed. Limit, remaining capacity, and reset time stay unknown until a
safe run-local observation records them.

Generated media remains unaccepted until an Observer sees the actual asset,
a distinct Reviewer records the four required quality dimensions, a distinct
Verifier validates integrity and independence without claiming visual
perception, and a human or Supervisor explicitly promotes it. Missing or
unknown evidence is an active promotion block, not a reason to defer acceptance
to an unspecified future workflow.
