# AgentLab Capability Acceptance Matrix

Updated: 2026-07-10

This matrix is the compact acceptance view for the current AgentLab operating
model. It maps the user's target capabilities to deterministic evidence, live
evidence, known gaps, and repeatable checks.

Chinese operator-facing overview: `docs/AGENTLAB_OPERATING_LOGIC.zh-CN.md`.

Machine-readable local aggregation now lives at:

```bash
./agentlab.sh capability-acceptance --out acceptance_runs/agentlab_capability_acceptance/current.yml
```

The representative production-chain map is generated by:

```bash
./agentlab.sh production-chain-audit --out acceptance_runs/agentlab_capability_acceptance/production_chain_audit.yml
```

The role/worker/chain consistency audit is generated by:

```bash
./agentlab.sh agent-role-chain-audit --out acceptance_runs/agentlab_capability_acceptance/agent_role_chain_audit.yml
```

The production-pack synthesis artifact smoke is generated by:

```bash
./agentlab.sh production-pack-synthesis-smoke --out acceptance_runs/agentlab_capability_acceptance/production_pack_synthesis_smoke.yml
```

The distinct returned role-session closure is audited by:

```bash
./agentlab.sh production-pack-role-session-audit --project AgentLab --task-id task_production_pack_role_session_live_20260710 --out acceptance_runs/agentlab_capability_acceptance/production_pack_role_session_audit.yml
```

The fresh governed four-role runner request is generated without provider calls by:

```bash
./agentlab.sh production-pack-role-session-request --out acceptance_runs/agentlab_capability_acceptance/production_pack_role_session_request.yml
```

The media-series scaffold audit is generated by:

```bash
./agentlab.sh media-series-scaffold-audit --out acceptance_runs/agentlab_capability_acceptance/media_series_scaffold_audit.yml
```

The user-action plan for pending internal live role-session work is generated by:

```bash
./agentlab.sh live-unblock-plan --out acceptance_runs/agentlab_capability_acceptance/live_unblock_plan.yml
```

The internal live-smoke readiness audit is generated by:

```bash
./agentlab.sh internal-live-readiness --out acceptance_runs/agentlab_capability_acceptance/internal_live_readiness.yml
```

It verifies that the remaining work is internal Writer/ArtifactProducer
role-session execution, that the safe follow-up commands are recorded, and that
no secret values are printed in the handoff. The older
`external_acceptance_readiness.yml` file is compatibility output only; the
canonical readiness contract is `agentlab_internal_live_readiness`.

The frontdesk-safe live handoff is generated by:

```bash
./agentlab.sh frontdesk-live-handoff --agent hermes --out acceptance_runs/agentlab_capability_acceptance/frontdesk_live_handoff.yml
```

It verifies that Hermes/DeepSeek V4 Pro is the optional internal FrontDesk,
Codex remains an external construction/audit worker, and declared pipelines can
use the direct closed loop without a FrontDesk session. Writer and
ArtifactProducer role sessions still own live generation.

The goal-level completion audit is generated by:

```bash
./agentlab.sh goal-completion-audit --out acceptance_runs/agentlab_capability_acceptance/goal_completion_audit.yml
```

It also validates that the cited source reports and per-goal evidence paths
exist in the current workspace before allowing an item to remain `pass`.

The original-objective requirement audit is generated by:

```bash
./agentlab.sh objective-requirement-audit --out acceptance_runs/agentlab_capability_acceptance/objective_requirement_audit.yml
```

It keeps the acceptance requirements explicit while reading the active scope from
`acceptance_runs/agentlab_capability_acceptance/goal_acceptance_scope.yml`. The
current scope requires full code-project and Crown Writer acceptance, accepts
production-pack synthesis at deterministic-scaffold level, and treats media as
readiness-only until a visual node-graph workflow replaces the black-box chain.

The current report status is `candidate`: this is the all-capabilities matrix and
still includes deferred media and production-pack provider-backed evidence. The
scoped goal/objective status is `partial`: deterministic orchestration,
code-project acceptance, and media execution readiness pass, but Crown Writer
returned-artifact acceptance remains candidate. Current
internal live-smoke readiness is `ready_for_internal_live_smoke`: routes, safety
checks, and non-private `agy` plus Grok/Hermes session health all pass. Only the
Writer selected item is in the active goal; media live artifacts are retained as
deferred evidence and do not block completion.

Status meanings:

- `pass`: deterministic local evidence exists and the current contract is met.
- `candidate`: live or dry-run evidence exists, but it is not production
  acceptance.
- `warn`: orchestration works, but quality, scale, or live-provider evidence is
  incomplete. The current capability report may have zero `warn` rows while its
  overall status remains `warn` because candidate/blocked rows still exist.
- `blocked`: the implementation has an adapter or contract, but live execution
  is waiting on credentials/provider stability.
